# Cloudflare Docs 風 文章構成

この skill は、Cloudflare 開発者ドキュメント(https://developers.cloudflare.com/)が採用する
文章構成(流れ)をテンプレートとして定めたものです。ドキュメントページの作成・刷新・構成レビューに使用します。

## 適用タイミング

- 新規ドキュメントページの作成時
- 既存ドキュメントページの刷新時
- ページ構成のレビュー時

## 全ページ共通の骨格

- タイトルは名詞句(動詞句にしない)
- 冒頭は「価値提案」1〜2文でページを始まる
- 末尾は必ず「Next steps」を置く
- 本筋からの逸脱(例外・注意点・細注)は `Note` / `Important points` / `Footnotes` に分離し、本文の流暢さを保つ
- 本リポジトリの aside 記法: 3 コロンのコンテナ(`:::note` / `:::caution` / `:::danger` / `:::tip` … `:::`)。Starlight が `starlight-aside` としてレンダリングする
- (任意) AI 入口の併設: llms.txt 案内 / 「Markdown で見る」リンク
- コマンドの出力例は、コマンドの直後に結果の説明文を置き、その下へ`text`コードブロックで示す。`bash`コードブロック内に出力や`# 出力例`のコメントを混在させない。

## ページ種別① 概要ページ(Overview)

「何 → 何が得られる → 使えること → 仕組み → コード → 次の一手」の順で説明的に流す。

1. **H1 + タグライン** — 一句で位置づけ
2. **利用可否バッジ** — 例:「Paid plan で利用可能」
3. **価値提案** — 1〜2文で何ができるか
4. **使いやすさ** — デプロイ/設定がどれだけ楽か
5. **「~できる」箇条リスト** — ユースケースを 3 程度で読者に刺す
6. **メンタルモデル一文** — 仕組みを一文で(「インスタンスはオンデマンド起動され、あなたのコードで制御される」)
7. **コード** — 主要な記法を複数並列提示(例: JS + 設定 JSON + TOML)
8. **CTA** — 始めるボタン / ダッシュボードへのリンク
9. **`## Next steps`** — カード形式(タイトル + **1 文の補足** + リンク)。1 文は必須
10. **`## More resources`** — `###` リンク + 1 文説明 の連打

## ページ種別② チュートリアルページ

「目的宣告 → 前提 → 実行(検証付き) → 復習 → 次へ」の順。命令形・第二人称で書く。

1. **導入 2 段落**
   - ①「本ガイドでは、~ します」でゴールを宣言
   - ②「この例では ~ が分かります」で得られる価値
2. **`## Prerequisites`** — 各前提を `###` に分割
   - 各前提 = なぜ必要 → どうやる → **確認コマンド + 成功/失敗の兆候** を必ず添える
3. **メインタスク** — 各ステップは 4 点セット
   - **コマンド → 何が起きる → 検証方法 → 失敗時の対処**
   - コマンドは複数記法をタブ切替で提示(例: npm / yarn / pnpm)
   - 罠・例外は `Note` で前置き(「初回は数分待て」等)
4. **`## Understanding the Code`(復習)** — 先ほど動かしたコードの"なぜ"を補足
   - `### Configuration` / `### Image` / `### Worker code` 等へ分解
   - プロパティは箇条で(「`defaultPort` は ~ を設定します」)
   - まず動かし、後で理解させる構成
5. **`## ダッシュボードでの確認`** — 目に見える成果で安心感
6. **`## Next Steps`** — リンク箇条

## ページ種別③ 参照ページ(Reference)

「項目を H2 に分割 → 各項目は "1 文の導き + 表 + 補足"」。散文を最小にし、表が主役。

1. **H1**(名詞句)
2. 各 **`##` 項目**
   - 導きの 1 文
   - **表**(事実・数値・制約は必ず表で)
   - 「どう指定するか」1 文 + リンク
   - 例外・別名は `Note`
3. **`## Footnotes`** — 表に載せきれない注釈を脚注化
4. 不足時の導線(support / フォーム / チケット)

## 横断文体規則(チェックリスト)

- [ ] 短文・短段落(説明文は基本 1〜2 文。長い説明は `###` や箇条に分割)
- [ ] リンクには必ず 1 文の補足を添える(裸のリンクは置かない)
- [ ] チュートリアルは命令形・第二人称("you" → 「~ します / ~ してください」)
- [ ] 実行・検証・失敗対応を同ステップに束ねる(分離しない)
- [ ] 同じ内容を複数記法で並列提示(JS + JSON + TOML、npm / yarn / pnpm)
- [ ] `Note` / `Important points` / `Footnotes` で本筋からの逸脱を分離
- [ ] 末尾に `Next steps` を置き、ページ間をカード(1 文説明付き)で繋ぐ
