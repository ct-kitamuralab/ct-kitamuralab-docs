CSV・Excel・DBの使い分けと、SQLiteの導入・基本操作を説明します。

## DBとは

**データベース（DB）は、データを保存し、検索・更新するためのものです。**

**リレーショナルDB**は、データを表として扱い、表同士をキーで関連付けるDBです。SQLiteもこの種類に含まれます。

## 基本用語

| 用語 | 意味 | 地点データでの例 |
| --- | --- | --- |
| テーブル | 同じ種類のデータを保存する表 | 観測地点の表 |
| <ruby>行<rt>ぎょう</rt></ruby>（レコード） | 1件のデータ | 1つの観測地点 |
| <ruby>列<rt>れつ</rt></ruby>（カラム） | データの項目 | 地点ID、コード、名前 |
| <ruby>主<rt>しゅ</rt></ruby>キー（PK） | 行を一意に識別する列、または列の組み合わせ。PK は Primary Key の略 | 地点表の地点ID |
| <ruby>外部<rt>がいぶ</rt></ruby>キー（FK） | 別の表などの主キー・一意キーを参照する列、または列の組み合わせ。FK は Foreign Key の略 | 観測表から地点表を参照する地点ID |
| <ruby>制約<rt>せいやく</rt></ruby> | 保存する値が守るルール | 必須、重複禁止 |
| <ruby>SQL<rt>エスキューエル</rt></ruby> | DBへ検索・更新を指示する言語 | `SELECT`、`UPDATE` |

DBの保存・検索・制約の検査を担当するソフトを、<ruby>DBMS<rt>ディービーエムエス</rt></ruby>（データベース管理システム）と呼びます。

DBでは、必須項目・重複禁止などを制約として定義できます。ただし、単位や日時の誤りなどは入力側でも検査が必要です。

## CSV・Excelとの使い分け

**条件検索、複数の表の関連付け、継続的な更新にはDBが向いています。** データ交換にはCSV、人が表を編集・確認する作業にはExcelを使うなど、併用もできます。

| 方法 | メリット | デメリット |
| --- | --- | --- |
| CSV | 単純なテキスト形式で、コードから読み書きしやすい | 複数の表や表同士の関係を、形式として管理できない |
| Excel | GUIがあり、表を見ながら直感的に編集・計算・グラフ作成ができる | コードから扱う際、Excel形式に対応したライブラリや、セル・シート・数式への対応が必要 |
| DB（リレーショナルDB） | 複数のテーブルを関連付け、検索・結合・集計・更新をコードから行える | テーブル設計やSQLの知識が必要 |
